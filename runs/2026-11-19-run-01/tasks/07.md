# 任務單 07：第 3 站：LLM 寫程式，真正的計算交給求解器

- 角色：concept
- data-wiki：system/03-code-and-solver.md topics/glossary.md
- data-points：K10 K11 K02
- 這張要講：
  - OptiMUS 用 Gurobi 或 cvxpy 寫 Python 程式；OptiGuide 的 **Coder** 組好提示，讓 LLM 寫程式
  - Chain-of-Experts 寫 **LP 格式檔**（求解器可以直接讀的模型文字檔，自製術語表）與 Gurobi 程式
  - 為什麼這樣分工：LLM 擅長讀懂文字，求解器擅長精確計算；LLM 會算錯，也會重複產生以前的解
  - 讓 LLM 直接找解的 OPRO，問題變大後就輸給專門的方法
  - 成本：OptiMUS 成功的執行，不含求解器時間，每次都在 7 分鐘內完成；平均用掉 4117.1 ± 1509.7 個 **token**
  - token 是 LLM 讀寫文字時的計算單位，用得越多，通常花的時間與費用也越多（自製術語表）
- 新術語（第一次出現，要用白話解釋）：Coder、LP 格式檔、token
- 建議元件：三個系統的做法用表格（系統｜LLM 寫什麼）；分工理由用 `<ul>`；成本放 `<p class="note">` 或 `<p class="answer">`
- 不要講：OPRO 的細節（留給第 12 張）；OptiGuide 讓資料留在求解器與資料庫（留給第 17 張）；評估器與 Safeguard（留給第 8 張）
- 注意：大綱這張約 169 個中文字、6 個列點（上限 180 字、6 個）。表頭的中文字也算在 180 字內。「不含求解器時間」要接在「每次都在 7 分鐘內完成」，不要接在 token 後面；4117.1 ± 1509.7 照抄。LP 格式檔與 token 的白話解釋都出自自製術語表，兩處都保留「自製術語表」字樣。
