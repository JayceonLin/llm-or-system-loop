# 第 2 站 建模：寫出決策變數、目標函數、限制式

## 這一站要做什麼

把第 1 站整理好的元素，寫成數學模型。一個最佳化模型有三個部分 [S1]：

- **決策變數（decision variable）：** 我們能決定的量，例如每天做幾杯紅茶。
- **目標函數（objective function）：** 想讓它越大或越小越好的式子，例如利潤。
- **限制式（constraint）：** 不能違反的條件，例如茶葉每天只有這麼多。

綜述用的標準寫法是：最小化目標 f(x)，同時滿足不等式限制 g_i(x) ≤ 0 與等式限制 h_j(x) = 0 [S1]。

## 做法一：先寫成中間表示（NL4Opt）

NL4Opt 的子任務 2，是根據第 1 站標出的元素，產生一種邏輯形式的「意義表示」，之後再轉成商用求解器能讀的格式 [S2]。

| 方法 | 準確率 |
| --- | --- |
| 基準模型（BART） | 0.610 [S2] |
| 比賽第一名 UIUC-NLP | 0.899 [S2] |
| ChatGPT（gpt-3.5-turbo），合併任務 | 0.927 [S2] |

**版本差異：** 依表格數字，ChatGPT 比第一名高 2.8 個百分點；論文討論段寫的是「高 2 個百分點」[S2]。兩個數字都記下，以表格算出的 2.8 為準。

## 做法二：LLM 直接寫出模型（OptiMUS）

OptiMUS 讓 LLM 用 Markdown 寫出變數、限制式與目標 [S3]。輸出是給人和下一站都看得懂的模型文件。

## 做法三：讓不同專家分工（Chain-of-Experts）

Chain-of-Experts 把建模拆給好幾個專家 [S4]：

- 術語解釋專家：補充領域背景。
- 參數、變數、限制、目標擷取專家：分別抽出模型的各個部分。
- 建模知識補充專家：提供建模技巧。
- 建模專家：寫出完整的數學模型，通常是混合整數規劃（意思見[新手術語表](../topics/glossary.md)）。

怎麼安排這些專家的順序，見[多代理人怎麼分工](../topics/multi-agent.md)。

## 要注意

- 模型寫錯是最難修的錯。後面的驗證回圈修得了漏掉的限制式，修不了一開始就想錯的模型 [S3]，見[驗證與修正](04-verify-and-repair.md)。
- 綜述把「如何結合領域知識」列為還沒解決的問題 [S1]。
