# 第 1 站 問題輸入：從文字到有結構的資料

## 這一站要做什麼

使用者通常用一段文字描述問題，例如「每天要做幾杯紅茶、幾杯奶茶，利潤才最高」。系統的第一步，是把這段文字整理成之後能建模的資料：哪些是我們能決定的量、目標是什麼、有哪些限制、數字是多少。

## 做法一：在文字裡標出元素（NL4Opt）

NL4Opt 競賽把這一步定義成「辨識語意實體」：在題目文字裡標出 6 種元素 [S2]。

| 元素 | 白話 |
| --- | --- |
| 變數 | 我們能決定的量 |
| 參數 | 題目給的數字，例如每杯利潤 |
| 目標方向 | 要越大越好還是越小越好 |
| 目標名稱 | 想最佳化的東西，例如利潤 |
| 限制方向 | 不超過、至少、等於 |
| 限制上限 | 限制裡的那個數字 |

這個子任務的第一名 F1 分數是 0.939，基準模型是 0.906 [S2]。F1 是同時考慮「標得準」和「沒漏標」的分數，越接近 1 越好。

## 做法二：要求結構化輸入，資料另外放（OptiMUS）

OptiMUS 不直接讀一般文字，而是要求使用者填一份有 6 個欄位的結構化描述，叫做 SNOP [S3]。數值資料另外存成 JSON 檔，只把資料的格式交給 LLM [S3]。

- **好處：** 很長的數據表不用塞進提示，LLM 只要知道資料長什麼樣子。
- **代價：** 輸入一定要是 SNOP，不能直接用一般文字 [S3]。

## 抽象模型與具體模型

- **具體模型：** 數值直接寫在題目裡 [S1]。
- **抽象模型：** 參數先用符號表示，數據之後再給 [S1]。

OptiMUS 把資料分開存放，就是在做抽象模型。

## 要注意

題目本身也可能寫錯。綜述檢查常用資料集時發現，錯誤來源包括題目敘述有邏輯漏洞、參數定義不清 [S1]。詳見[怎麼評估一個系統](../topics/evaluation.md)。
