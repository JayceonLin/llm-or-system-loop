# 自製範例：手搖飲店走完五站

> **這一頁是自製範例，不是來自來源論文。** [自製] 用一題小問題，示範一個用到 LLM 的 OR 系統每一站在做什麼，五站的說明見[總覽](../overview.md)。每一站的做法參考 NL4Opt [S2]、OptiMUS [S3] 與 OptiGuide [S6]。

## 題目

一家手搖飲店每天要決定紅茶與奶茶各做幾杯。每杯紅茶利潤 20 元、每杯奶茶利潤 30 元。兩種飲料每杯都要用 10 公克茶葉，店裡每天最多只有 5,000 公克茶葉；奶茶每杯另外要 150 毫升鮮奶，鮮奶每天最多 30,000 毫升。怎麼安排利潤最高？[自製]

## 第 1 站 問題輸入：標出元素

| 題目裡的文字 | 元素類型 |
| --- | --- |
| 紅茶杯數、奶茶杯數 | 變數 [自製] |
| 利潤最高 | 目標方向：最大化 [自製] |
| 20 元、30 元 | 參數：每杯利潤 [自製] |
| 最多 5,000 公克 | 限制方向「不超過」與限制上限 [自製] |

這就是 NL4Opt 子任務 1 在做的事：在文字裡標出元素 [S2]。

## 第 2 站 建模

- 決策變數：x₁ = 紅茶杯數，x₂ = 奶茶杯數 [自製]
- 目標函數：最大化 20x₁ + 30x₂ [自製]
- 限制式：茶葉 10x₁ + 10x₂ ≤ 5000；鮮奶 150x₂ ≤ 30000；x₁, x₂ ≥ 0 [自製]

## 第 3 站 寫程式交給求解器

```python
import pulp

def solve(tea=5000, milk=30000):
    m = pulp.LpProblem("tea", pulp.LpMaximize)
    x1 = pulp.LpVariable("x1", lowBound=0)   # 紅茶杯數
    x2 = pulp.LpVariable("x2", lowBound=0)   # 奶茶杯數
    m += 20 * x1 + 30 * x2                   # 目標：利潤
    m += 10 * x1 + 10 * x2 <= tea            # 茶葉
    m += 150 * x2 <= milk                    # 鮮奶
    m.solve(pulp.PULP_CBC_CMD(msg=False))
    return x1.value(), x2.value(), pulp.value(m.objective)

print(solve())            # (300.0, 200.0, 12000.0)
print(solve(tea=6000))    # (400.0, 200.0, 14000.0)
```

這段程式已用 PuLP 3.3.2 實際執行，輸出如註解 [自製]。

## 第 4 站 驗證：把答案代回去

- 茶葉：10 × 300 + 10 × 200 = 5000，剛好用完 [自製]。
- 鮮奶：150 × 200 = 30000，剛好用完 [自製]。
- 利潤：20 × 300 + 30 × 200 = 12000 元 [自製]。

兩條限制都滿足，答案可以採用。系統裡這一步會交給程式自動做，見[驗證與修正](../system/04-verify-and-repair.md)。

## 第 5 站 解釋結果與 what-if

- **白話回答：** 每天做紅茶 300 杯、奶茶 200 杯，利潤 12,000 元；茶葉和鮮奶都剛好用完 [自製]。
- **what-if：** 店長問「如果茶葉每天多進到 6,000 公克，利潤會怎麼變？」系統只要改一個數字重算：紅茶變成 400 杯、奶茶仍是 200 杯，利潤變成 14,000 元 [自製]。

這就是 OptiGuide 在做的事：使用者用文字問 what-if，LLM 寫程式改條件、交給求解器重算，再翻成白話 [S6]。
